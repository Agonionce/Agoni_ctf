# Agonionce R8.6 Completion Report

## Result

R8.6 implements the Challenge Completion and Experience Consolidation
Pipeline. Once an imported challenge run has been persisted, Agonionce now
collects its run status, current-challenge Intelligence, experiments, evidence,
and Artifact metadata into deterministic private outputs:

- `report.md`;
- `writeup.md`;
- `lessons.md`;
- `experience_candidates.json`.

The completion path is read-only with respect to `RunState` and
`IntelligenceState`. It does not call an LLM, perform a Tool action, infer a
missing exploitation step, store a challenge answer in global memory, or merge
an experience candidate automatically.

## Architecture

The new code lives in `agent/completion/`:

- `models.py` owns `ChallengeReport`, `ExperienceCandidate`, and
  `ExperienceReviewStatus`.
- `collector.py` owns `CompletionCollector`, persisted-run loading, and the
  post-run `ChallengeCompletionPipeline` coordinator.
- `report.py` renders the deterministic analysis report and lessons.
- `writeup.py` renders an evidence-bound writeup draft.
- `experience.py` owns rule-driven extraction, per-challenge candidate JSON,
  review state, and approved global Experience conversion.

```text
ChallengeManifest
  + RunState
  + IntelligenceState
  + Experiment history
  + Evidence
  + Artifact metadata
        |
        v
CompletionCollector (read-only)
        |
        v
ChallengeReport
  +-- ReportGenerator -> report.md
  +-- WriteupGenerator -> writeup.md
  +-- Lessons -> lessons.md
  +-- ExperienceCandidateExtractor -> experience_candidates.json
```

`Workflow` invokes this pipeline after the existing R8.5 run binding succeeds.
The integration is outside `AgentRuntime`: Planner, Analyzer, ToolRuntime,
PolicyEngine, ApprovalManager, and Runtime contracts are unchanged.

## Completion Flow

```text
Challenge Import
  -> Existing Agent Run
  -> R8.5 run-NNN snapshot
  -> CompletionCollector
  -> report.md
  -> writeup.md
  -> lessons.md
  -> PENDING experience candidates
  -> explicit review
```

`CompletionCollector` validates that the manifest, run, and Intelligence state
share the same challenge ID. It copies only report-safe fields into a new
`ChallengeReport`; credentials are never read from the Intelligence credential
collection, Tool arguments are omitted, and Artifact file contents are not
loaded. Source objects are not mutated.

The latest-run loader selects the newest `runs/run-NNN/run.json` that was fully
bound. It reads the adjacent Artifact manifest and top-level
`intelligence.json` without consulting `config.json`.

## Report Design

`report.md` contains:

```text
Overview
Domain
Timeline
Key Findings
Experiments
Evidence
Result
Lessons
```

The report records persisted run status instead of a challenge answer. Timeline
entries come only from Experiment timestamps and Evidence timestamps. Findings,
expected results, actual results, and Evidence observations are rendered from
the collected model. Empty sections say that no persisted data exists.

`writeup.md` contains:

```text
Challenge Description
Recon
Analysis
Exploitation Process
Evidence
Solution
Flag
Lessons Learned
```

The draft never fills gaps with model speculation. Its exploitation process is
the recorded Experiment history, and its Evidence section is the recorded
Evidence collection. Solution reports only the persisted run status. The Flag
section deliberately says that the completion pipeline did not persist a flag.

## Experience Review Flow

Experience candidates keep current-challenge Intelligence separate from global
Experience:

```text
ChallengeReport + Experiment history + Lessons
  -> deterministic rule match
  -> sanitized ExperienceCandidate(PENDING)
  -> experience_candidates.json
       | approve                    | reject
       v                            v
  global ExperienceStore       local REJECTED status
```

Candidates contain only a category, generic pattern, strategy, lesson, opaque
source challenge ID, confidence, and review status. Candidate IDs are stable for
the same challenge and rule so regeneration preserves completed review state.

Approval converts one candidate into an existing R7 `ExperienceRecord` and
writes it to `experiences/global/experience.json`. It is idempotent. Rejection
does not create or modify the global store. An approved candidate cannot later
be rejected, and a rejected candidate cannot later be approved implicitly.

No LLM, embedding, vector store, graph database, model update, or Skill rewrite
is used.

```text
└── challenges/
    └── challenge-name/
        ├── challenge.json

        ├── experiments.json
        ├── analysis.md
        ├── report.md
        ├── writeup.md
        ├── lessons.md
        ├── experience_candidates.json

```

`analysis.md` and `description.md` are retained for R8.5 compatibility and
historical continuity. The per-challenge folder is private runtime data; it is
not the global reusable Experience store.

## CLI Usage

Generate completion artifacts from the latest persisted run:

```bash
python main.py challenge report <challenge-id>
python main.py challenge writeup <challenge-id>
python main.py challenge extract-experience <challenge-id>
```

Review candidates:

```bash
python main.py experience candidates list
python main.py experience candidates approve <candidate-id>
python main.py experience candidates reject <candidate-id>
```

All commands accept explicit root/store options for isolated validation. The
candidate commands use the governed default paths directly and do not read
`config.json`.

## Security Boundary

- Completion never reads `config.json`, `.env`, an API key, or an Artifact's
  file contents.
- Credential objects are excluded from the completion report.
- Tool argument dictionaries are excluded from the report and writeup.
- Common secret assignments and flag-shaped values are redacted from private
  report fields.
- Candidate extraction fails closed for text containing password, token,
  cookie, secret, flag, or credential terms.
- Candidate models repeat that validation on construction and JSON restore.
- No candidate enters global Experience until explicit approval.
- Global records contain generic strategy only, never target URLs, IP
  addresses, private answers, credentials, or challenge-specific payloads.
- The demo uses only a temporary workspace, fake state, and a loopback URL; it
  opens no socket and performs no Tool execution.

## Remaining Risks

- Report and writeup quality is bounded by the structure and provenance of the
  stored Intelligence and Evidence; the generator intentionally does not fill
  missing narrative gaps.
- Rule-based candidate extraction currently recognizes a small set of generic
  domain patterns and may produce no candidate for a valid completed run.
- Review is local CLI state, not a multi-user approval system.
- A process interrupted after run binding but before consolidation may require
  an explicit `challenge report`, `challenge writeup`, and
  `challenge extract-experience` retry.
- Per-challenge reports remain private runtime data and may still include
  authorized target-specific observations after redaction; they must not be
  committed or copied into global Experience.
- There is no automatic learning, Skill evolution, knowledge graph, embedding,
  vector search, model-weight update, multi-agent behavior, scanner, payload
  generator, or real exploit automation.

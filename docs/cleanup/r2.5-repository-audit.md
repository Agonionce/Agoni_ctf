## Keep

- `agent/runtime/`: R0 typed orchestration.
- `agent/tools/`, `agent/policy/`, `agent/workspace/`, `agent/artifacts/`: R1
  controlled execution boundary.
- `agent/intelligence/`: R2 structured knowledge and checkpoint layer.
- `agent/workflow.py`, `agent/checkpoint.py`: active CLI workflow and checkpoint
  compatibility entry points.
- `cli/`, `ctf_platform/`: active command and challenge adapter surfaces.
- `prompts/r0_*.md`: active Planner/Analyzer prompts.
- `skill/`, `skills/`: active deterministic skill system and domain content.
- `tests/`: active R0–R2 regression and local-only integration tests.
- `docs/architecture/r0-core-runtime.md`, `r1-controlled-execution.md`, and
  `r2-intelligence-state.md`: current architecture documentation, subject to
  wording cleanup.
- `LICENSE`: standard Apache License 2.0 text with no project-specific
  marketing content; preserve unchanged.
- `config.py`, `config_template.json`, `.gitignore`, requirements files, and
  `main.py`: active project infrastructure.

## Review

- `AGENTS.md`: useful contributor guidance but structurally and technically
  stale; rewrite for the current architecture.
- `utils/llm_request.py`, `utils/text.py`: active OpenAI-compatible request and
  text helpers mixed with stale role aliases or unused repair helpers; retain
  only the active path.
- `requirements.txt`, `requirements-lock.txt`: contain packages used only by
  the retired tool/agent path; reconcile after removals.
- `docs/inputer_and_submiter.md`: active adapter topic but stale platform-
  specific examples and naming; replace with a concise current development
  guide.
- `.github/`: absent. No GitHub workflow or template requires migration.

## Remove candidates

Removal requires both a repository-wide reference check and a passing test run.

- The retired monolithic solver, analyzer, and chat-memory modules: superseded by
  R0 Runtime and R2 Intelligence; referenced only inside the same retired
  implementation cluster.
- `utils/tools.py`, `ctf_tool/`, `prompt.yaml`: retired dynamic BaseTool path;
  the active Planner uses `agent/tools/ToolRegistry` and `prompts/r0_*.md`.
- `docs/cli_ui_redesign.md`, `docs/multi_agent_design.md`,
  `docs/ssh_shell_to_local_bash_design.md`,
  `docs/architecture/upstream-baseline.md`: historical plans that describe a
  different repository identity or retired architecture.
- `Dockerfile`: unused SSH container with a hard-coded root password and a
  broad offensive-tool image, incompatible with the current safety boundary.
- `1.png`, `qq_group.jpg`, `tch_logo.png`: prior branding, community promotion,
  or unrelated event artwork.
- `.claude/settings.local.json`: machine-specific paths, author-local command
  allow-list, and stale repository identity; unsuitable for a shared repo.

## External metadata

- `LICENSE`: preserve unchanged. Apache License 2.0 is a legal distribution
  file, not a branding document.
- `NOTICE`: not present.
- `CONTRIBUTING.md`: not present; development guidance will live under
  `docs/development/` and `AGENTS.md`.
- `.github/`: not present; no workflow, issue template, release config, or pull
  request template is available to review or remove.

## Remediation outcome

- All remove candidates listed above were deleted after the reference-closure
  check.
- The three binary branding assets were verified visually before deletion.
- `README.md`, `AGENTS.md`, configuration metadata, dependencies, and active
  architecture wording were rewritten for Agonionce.
- Current documentation is organized under `docs/architecture/`,
  `docs/cleanup/`, `docs/development/`, and `docs/roadmap/`.
- The active test suite passed after removal, confirming that no retained
  runtime path depended on the deleted cluster.
- Ignored user/runtime data and local virtual environments were not removed or
  inspected for content.
- Git remote metadata was not changed because no new hosting URL was supplied;
  it is outside the tracked project identity audited here.
